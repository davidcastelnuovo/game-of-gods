# צינור נכסים תלת־ממד (Three.js)

**פרויקט:** משחקי האלים (Game of GODS)  
**מנוע:** Three.js בדפדפן — **לא** Unity. המטרה היא תהליך עבודה דמוי־Unity (תיקיות, ייבוא, prefabs) מעל הקוד הקיים.

---

## 1. עקרונות

| נושא | בהחלטה |
|------|--------|
| בלוקי ווקסל | ממשיך ב-`InstancedMesh` + טקסטורות פיקסל מ־canvas (כמו היום) |
| אביזרים / יצורים / מקדשים | מודלים **mesh** (glTF/GLB), Group ב-Three.js |
| מקור אמת בעולם | בלוקים ב-JSON שמירה; meshes כ-prefab + transform בעתיד |
| יצירה במשחק | שחקן/מעצב מניח **prefab** מספריית אובייקטים (בדומה ל-Unity Place) |

---

## 2. מבנה תיקיות (יעד)

```
client/
  src/assets/
    models/          # קבצי .glb / .gltf (עמודים, סירות, פסלים)
    textures/        # PNG/JPG — רצויות POT, סגנון פיקסל או ריאליסטי לפי יחידה
    audio/           # SFX / מוזיקת רקע (mp3/ogg)
    manifests/       # JSON: מפתח prefab → נתיב קובץ + קנה מידה + נקודת עיגון
```

בשרת (אופציונלי לעתיד): `server/public/assets/` להגשת קבצים גדולים עם cache; כרגע static מהשורש.

**כלל שמות:** `kebab-case`, קידומת אזור אם צריך — `cyclades-boat.glb`, `creature-sea-serpent.glb`.

---

## 3. ייבוא glTF / GLB

1. ייצוא מהכלים (Blender, או AI — ראה סעיף 5) ל-**glTF 2.0** או **GLB** (קובץ יחיד).
2. בקוד (שלב עתידי): `GLTFLoader` מ-`three/examples/jsm/loaders/GLTFLoader.js`.
3. אחרי טעינה:
   - `scene.traverse` להדלקת `castShadow` / `receiveShadow` לפי המדיניות של המשחק.
   - `mesh.scale.set(s,s,s)` לפי `manifests/*.json`.
4. **אופטימיזציה:** Draco compression אם הגודל עולה; mesh יחיד לפרופ סטטי, סקלטון רק ליצורים מונפשים.

---

## 4. ווקסל מול Mesh

| סוג | שימוש | רינדור |
|-----|--------|--------|
| **Block** | טריין, בנייה, מים | `InstancedMesh`, id מ-`BLOCK_DEFINITIONS` |
| **Prop / Prefab** | עץ מפורט, רהיט, סירה, מקדש | `Group` + children meshes |
| **Creature** | יצור עם אנימציה | GLB + `AnimationMixer` (מאוחר יותר) |

אין להמיר בלוקים ל-mesh אוטומטית — זה פוגע בביצועים וברשת. העתקת מבנה קיים (מקדשים בקוד) ל-GLB היא שלב מעבר אופציונלי.

---

## 5. כלי AI לתלת־ממד (קונספטואלי)

אין נעילה לספק אחד — זרימה כללית:

| כלי (דוגמה) | תפקיד טיפוסי |
|-------------|--------------|
| Meshy / Tripo | טקסט→מודל או תמונה→מודל מהיר לפרופס |
| Scenario | סגנון עקבי + וריאנטים לטקסטורות |
| Rodin (Hyper3D) | אובייקטים איכותיים יותר, פחות כמות |

**זרימת עבודה מומלצת:**

1. פרומפט + רפרנס סגנון (קיקלאדות / יוון עתיקה).
2. ייצוא GLB → תיקון ב-Blender (scale 1 unit = 1 meter, Y-up).
3. שמירה ב-`assets/models/` + רישום ב-manifest.
4. בדיקה ב-Vite dev לפני merge.

---

## 6. יצירה במשחק (Place Prefab)

תכנון עתידי (לא מיושם במלואו היום):

1. **ספריית אובייקטים** ב-UI (כבר קיים רעיון ספרייה למבנים).
2. בחירת prefab → raycast לקרקע → `instantiatePrefab(id, x, y, z, yaw)`.
3. שמירה בעולם: מערך `props: [{ prefab, x, y, z, ry, ... }]` לצד `blocks`.
4. מולטיפלייר: הודעת WS חדשה (למשל `propPlace`) — רק אחרי שלב סמכות (מפת דרכים שלב C).

---

## 7. וו עתידי ל-AI בתוך המשחק

רעיון מאוחר: פקודה בממשק המעצב («צור סירת דיג אגאית קטנה») → קריאה ל-backend / MCP מאובטח → קובץ GLB נשמר תחת `assets/models/generated/` → נרשם ב-manifest → מופיע בספרייה. דורש:

- מגבלות גודל ופוליגונים
- סינון תוכן
- חתימת משתמש/עולם על נכסים שנוצרו

זה **וו** בלבד — הפרויקט לא תלוי בו ל-MVP.

## 8. צ׳קליסט לפני merge של נכס חדש

- [ ] GLB בגודל סביר (&lt; ~5MB לפרופ; יצור עד ~15MB)
- [ ] יחידות וסובב Y תואמים לעולם המשחק
- [ ] צללים לפי מדיניות המפה (קבוע: shadows on לפרופוסים גדולים)
- [ ] רשומה ב-manifest עם `id` יציב
- [ ] RTL/עברית בשם התצוגה ב-UI, לא בנתיב הקובץ
- [ ] רישיון שימוש מתועד (מקור AI / אמן / רכש)
